# 开头写法与选择

以下是对用户案例的编辑整理，按用途合并近义写法；不是统计得出的成功率，也不是平台认证公式。默认“自然、具体、内容能兑现”。案例 ID 可在案例卡或检索脚本中查到。

## 先看你有什么，再选怎么开

| 已有内容/素材 | 适合入口 | 写作骨架（填真实内容） | 使用条件与来源 |
| --- | --- | --- | --- |
| 能解决一种具体困扰 | 处境共鸣 | 具体情境或动作 + 卡在哪里 + 能拿到的帮助 | 比“你焦虑吗”具体；H07e48f8b49、Hfd61083d50 |
| 有成品、变化或实测画面 | 结果前置 | 先亮可见结果 + 交代限制或条件 + 接做法 | 没有真实结果就用操作演示，不编经历；H594b2b086a、H38e816c91d |
| 正文确实有方法、清单 | 明确收益 | 谁遇到什么问题 + 本条给什么可用东西 | 承诺具体且不越过内容能力；H6611fc0b22、H07e48f8b49 |
| 有两种可公平比较的方案 | 对比/反差 | 同一件事的 A 与 B + 具体差别 + 拆原因 | 对比条件应交代；身份、成本、数字都真实；H874b15a8b5 |
| 有与常见做法不同且能解释的发现 | 反常识 | 常见做法的局限或反直觉结论 + 必要范围 + 马上解释 | 不是为了反对而反对；H594b2b086a、H07e48f8b49 |
| 有能回答的真实疑问 | 具体问题 | 一个与目标观众有关的问题 + 很快开始给答案 | 省去“你知道吗”；Hfebc189d67、Hdf97766548 |
| 有真实经历或明确的故事素材 | 事件/冲突 | 正在发生的动作 + 阻碍或意外 + 开始推进 | 不借别人的失败、人设、金额讲“我”；H674d82863f、H4c913dcd65 |
| 有观众想弄清的具体反常现象 | 信息缺口 | 交代已知情境 + 留一个明确未知点 | 下一段增加信息；不能只有“有个秘密”；H07e48f8b49 |
| 有真实试验、限制条件或挑战 | 挑战任务 | 有限资源/条件 + 具体任务 + 开始做 | 没做完就说计划，不写“我已经成功”；H21d6094401 |
| 有可见细节或能完成的动作 | 画面先说话 | 展示/打开/进入/指出 + 一句讲清看点 | 用一镜一个动作，特效按需；H38e816c91d、H7bb1e3782e |

“人群点名”和“真实数字”可以叠加到以上任一种：例如“第一次租房”“只用手机”“同一份材料”。相关性比年龄标签堆砌更重要。数字只在真实且帮助理解时用；不是越多越可信。H483d77fe51 中可迁移的是按需要找关键词，不能迁移其关于长相、人群价值及算法的绝对判断。

## 常见题材的起步选择

- 知识、教程、工具：优先明确收益/演示结果/具体问题，正文立刻给一项可用信息。
- 生活、vlog：优先任务/意外/具体生活切片，别只报“某某的一天”；没有意外可直接给一个值得看的日常细节。
- 测评、产品：有素材先看真实对比与限制。没有测试结果时说明“这次测什么”，不预判赢家。
- 经验、观点：用真实处境、结论或一次复盘；新手无需扮演专家。
- 情感、成长：先说具体瞬间，语气与用户相近，避免诊断式替别人断言心理原因。
- 商家、探店：价格/使用场景/实际作品有则展示。折扣、名额、效果未确认就不写。
- 剧情/AI 短片：动作、人物目标与阻碍优先。视觉奇观只有与故事有关才有用。

## 相互矛盾的原说法怎么处理

| 案例中的说法 | 本 Skill 的处理 |
| --- | --- |
| “永远不要用疑问句”与“提问式开头好用” | 都保留为观点。泛问句信息少就改陈述；具体问题能引出答案就可保留。H594b2b086a vs Hfebc189d67 |
| “黄金三秒决定生死”与“黄金三秒已经死了” | 不采纳时代/算法断言。先尽早交代主题，再检查引入是否拖延；语气由内容和用户决定。Hdf97766548 vs Hfd61083d50、Hee0e774006 |
| “连环否定、树立敌人、故意让人抬杠” | 可学习明确立场、排除误区和问题结构；不刻意羞辱群体或靠空争议替代信息。H65c0b24350 |
| “只问不答” | 可以延迟一小段答案以形成故事，必须推进和兑现，不整段连续空问。H65c0b24350 |
| “数字凸显专业、数字自带真实” | 数字不证明真实；需有素材或用户事实。没有证据就写可展示步骤。H07e48f8b49 |
| “一秒精通、一招搞定、谁用谁火” | 把承诺改为具体可交付内容，例如“演示一种做法”。复杂问题不保证普遍结果。H231c5816c7、H65c0b24350 |
| “照抄一句就能爆” | 只迁移人群、情境、差异、动作的结构，重新组织语言。H1ca3ee01da |

借势不能变成伪造引用：H231c5816c7 / H2bee5c6f52 的原文把自己说的话改挂到名人名下，这是反例。相关名人观点或热点没有可靠出处，就不用作权威背书。

## 把普通句子改具体

以下为新写的演示，不是原 CSV 引文；涉及物品或画面须按真实素材调整。

- 普通：“今天分享怎么整理桌面。”
  改：“桌面刚收好，一工作又乱了？先给这三样东西安排固定位置。”
  正文马上指出三样物品，若正文只讲两样则把数量改成两样。
- 普通：“你知道 AI 为什么答非所问吗？”
  改：“你只丢给 AI 一句‘帮我写’，它很难猜到你想要什么。把要求补成这三部分。”
  正文展示任务、背景和输出要求，这是提问演示，不承诺所有工具都能完成。
- 普通：“看看我做饭的一天。”
  改：“冰箱里只剩这两样，我想试着把晚饭做出来。”
  先拍冰箱和食材，这是任务型草案；用户实际食材不同就改。

## 首镜头选择

一台手机就可以执行的方案优先：

| 文案入口 | 第一镜头 | 屏幕短字 | 下一镜或正文 |
| --- | --- | --- | --- |
| 处境共鸣 | 人物正在做那个动作 | 具体困扰，约一行 | 指出一个细节或开始解释 |
| 结果前置 | 成品/屏幕结果近景 | 给结果起准确短名 | 回到操作过程 |
| 对比 | 同构图展示两种结果 | A/B 的真实条件 | 解释一个差别 |
| 具体问题 | 物品、错误步骤或截图 | 一句简短问题 | 直接纠正/回答 |
| 任务/故事 | 当场开始操作或进入事件 | 真实限制或目标 | 接阻碍与下一步 |

字幕不逐字复读长口播；用最关键几个字即可。停顿、放大、音效都为理解服务。原表中的蒙版、抠像、立体字、快切是进阶选项；用户明确要剪辑教程再展开，且软件现有功能需另行确认。
